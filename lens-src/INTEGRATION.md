## Minimal editor setup

1. Retain **Spectacles Interaction Kit** and **Spectacles UI Kit**. The source imports `Button` from `SpectaclesUIKit.lspkg/Scripts/Components/Button/Button`. The observed installed package provides `Button.getTypeName()`, `size`, `setVariant`, `initialize` and `onTriggerUp.add`.
2. Put the SIK prefab before the experience in the hierarchy. The main camera needs world Device Tracking. Preserve the starter camera/render target configuration.
3. Provide a cube mesh whose bounds are **−0.5 to +0.5 cm** on every axis. A 100cm cube makes the model 100× too large. Provide a material exposing `mainPass.baseColor` and a legible regular or medium Font. A softly lit PBR material with broad fill lighting shows the authored furniture normals; an unlit material is a functional fallback. Assign the optional `evidenceMaterial` input to an unlit material so path/witness/selection colors and QR contrast stay independent of furniture lighting. The component clones materials into warm linen/oak and bright mint/amber evidence colors; normal UI does not depend on dark text.
4. Create an empty `Open Door` SceneObject at identity, attach `OpenDoorExperience`, and assign `cubeMesh`, `baseMaterial`, `font` and an unlit `evidenceMaterial`. The verified companion URL defaults to `https://open-door-weld.vercel.app`; assign `companionBaseUrl` to another verified HTTPS deployment if needed. No button prefab or per-object inputs are required.
5. Run Preview. The miniature room is centered at `(0, −3, −125)` cm with scale `.10`, pitch `.40` and yaw `−.18` radians; UI faces the default identity camera at z=−95 cm. Overview UI spans approximately x±23 and y−22 to +23cm. Edit mode adds contextual rows down to y−26cm; Fine adjust uses two rows. This composition was inspected in SPECS 27 Interactive Preview. Recheck framing/legibility when changing the camera or display configuration. If using another camera pose, place the **experience root** relative to it at startup. Miniature/full-scale mode never moves the camera.

The runtime uses `RenderMeshVisual`, `Text.layoutRect`, `Rect.create`, `quat.angleAxis`, `MeshBuilder`, UI Kit Button and `InternetModule.fetch` APIs inspected in the installed packages and Lens declarations. It does not use browser DOM or Node APIs. `require("LensStudio:InternetModule")` supplies the supported native HTTP client; no added component input or credential is required. The installed API has no AbortSignal option, so cancellation invalidates the request token instead of claiming to abort transport. The bounded backend request may finish after local cancellation. No URL-launch method was found in the observed native declarations, so the share handoff is a QR scan rather than a speculative native openURL call.

## Computed repair interaction flow

The current authored revision adds a real bounded search and reduces the overview to a compact product/room title, two task states, the room and three actions: **Find changes**, **Rehearse**, **Room / plan**. Source checks, shared engine tests and the [actual native repair pass](../devpost/native-repair-preview.md) pass. Earlier direct-edit evidence remains documented separately.

- **Find changes** posts the exact input, request ID and generation to `companionBaseUrl + /api/v1/repairs` with the installed `InternetModule.fetch`. The production endpoint runs the same bounded `createRepairSearch` core. A 25-second timeout, request serial, generation, source revision and full input fingerprint gate every response. The envelope, scope, response text (524,288 code units), candidate count (at most three), poses, motions, move metrics and proposal identity are checked. Each returned alternative is independently reconstructed and reverified locally, one per Update, including protected inputs, every final placement, the complete preferred route, the door sweep and the extra-reserve certificate. Server-provided display paths/results are replaced by the fresh local evaluation. No alternative is displayed until all returned candidates verify. **Cancel search**, **Profile** and **Edit locks** stay available.
- Network, malformed-response and verification failures retain the room and offer **Retry online**, **Try offline** or **Back**. Offline search is an explicit user choice, with a visible notice that it may take several minutes. It advances the portable job with `step(6)` on Update; the six-millisecond value is a cooperative target, not a hard native deadline. No automatic retry or silent offline job runs. Six unlocked objects, three moved pieces, finite contact/radial destinations, an eight-layout beam, 400 evaluations and 12,000 expanded route states bound either search. Other objects' original footprints remain excluded from candidate destinations, so coordinated swaps are outside this domain.
- A result shows up to three independently verified alternatives. **Next option** cycles them. Ranking compares all reserve domains by pieces moved and then translation/rotation cost; only the actual first-ranked result is labeled **Least movement found**. Higher-clearance alternatives must have a larger certified reserve. Tiny margins are stated explicitly. Route reserve is beyond the unchanged profile's buffer and uncertainty; door reserve additionally separates the leaf from furniture. The door calculation does not reuse the device buffer.
- Candidate furniture appears at its proposed destination. Amber floor outlines mark original positions; mint arrows and centimetre labels show displacement. These arrows do not claim a collision-free furniture-relocation trajectory. **Original / new** switches the view without changing numerical inputs, history or revision. **Mini / 1:1** changes only presentation. Sampled occupied-footprint outlines make the route's full spatial footprint visible at either scale; continuous safety evidence still comes from the numerical verifier.
- Furniture far-ray drags are disabled during search and proposal review, including when viewing the original positions. The persistent SIK targets remain alive. Closing the review restores source positions before direct editing becomes available again. Source hash or generation changes invalidate a pending search. `getVerificationState()` reports committed results separately from displayed proposal results, search metrics, transport status, request ID/generation, round-trip time, local verification duration/count, generated count, proposal moves/reserves, selected option, pending Apply and history length.
- **Apply** queues a commit for the next Update. The core rechecks the source hash/revision, every protected input, lock, final placement, continuous trajectory, door sweep and claimed reserve. All accepted poses form one history entry and one revision. The retained preferred trajectory is independently validated under the original profile and is the path that plays. An unreviewed profile opens the profile controls first, then resumes rehearsal. A failed or stale proposal cannot commit.
- **Room / plan → Profile** shows width, length, buffer and uncertainty. Width ±5cm and buffer ±1cm are actual profile edits: they increment the revision, recompute and invalidate proposals. **Use profile** confirms the shown assumptions. Pivot/reverse remain the explicit provided movement model; these values are not inferred from the viewer.
- **Room / plan → Edit room** exposes selection, Fine adjust, Lock / unlock, Undo and Back. Unlocked furniture supports genuine far-ray floor-plane drag with one deferred commit. Fine adjust has both ±X/±Y 10cm steps and 15° rotation. Boundary and overlap edits are rejected. The bed remains locked in this example; other furniture can be locked. Named fixture-move buttons are no longer part of the user interface; the diagnostic `suggest` method remains for compatibility.
- **Room / plan → Tasks / scale** exposes the selected task, miniature/1:1, original-layout comparison and Scope. Scope contains provenance, geometry limitations and the untested hardware boundary instead of a persistent multi-line footer. Search scope is also available during proposal review.
- **Room / plan → Keep plan → Show QR** encodes the exact committed input and revision. The QR is the user-facing handoff; the companion reevaluates that input and provides SVG/JSON downloads. Existing share fragments remain compatible. A share fragment identifies the room/profile/tasks, not a permanently prescribed trajectory; a fresh companion visit may choose another valid route. `exportPlan()` is a diagnostic method outside the menus and includes the actually retained native trajectory and accepted repair selection (source/proposal/input fingerprints, moves, extra reserve target and certified bound) in its evidence. This selection is cleared on subsequent model edits. Ordinary adaptive clearance bounds can be looser than the separately verified target-reserve certificate.

## Direct spatial furniture manipulation

The controller now imports SIK's installed `Interactable` and `InteractorEvent` types. Each furniture root receives a child `Physics.ColliderComponent` with `Shape.createBoxShape()` sized to its explicit furniture dimensions **before** creating the Interactable, so SIK's onAwake registration discovers that collider. `targetingMode=2` selects the package's Indirect/far-ray mode; filtered pinch, instant drag and retained hover are enabled. This uses Interactable events directly instead of unconstrained InteractableManipulation translation, because floor-plane placement and transactional commits are required.

Aim the far ray at an unlocked piece, pinch, move the ray across the floor, and release. The runtime reads the real `event.interactor.startPoint` and `direction`, transforms two world-ray points through `content.getTransform().getInvertedWorldTransform()`, and intersects the resulting ray with local y=0. That accounts for the miniature's tilt/scale and full-scale placement without assuming a world-horizontal floor. The initial floor grab offset is preserved to prevent snapping the furniture center under the ray.

During drag only the furniture's visual root moves. Route visuals hide, the status explicitly reads **PLACEMENT PREVIEW**, and `Core.placementIssue` provides provisional placement feedback. Numerical inputs, revision, history, share data and task evaluations are untouched during drag updates. Release queues one commit for the controller's next Update, outside SIK event propagation; the accepted move goes through `Core.moveObject`, adds one history entry/revision and evaluates once. Illegal placements reconstruct the original room without a revision. Cancellation, mode changes and other scene rebuilds discard the preview. Locked objects—including the permanently locked bed—never start a drag. Nudge, rotation and lock controls remain available.

`getVerificationState()` additionally exposes `dragActive` and `dragCommitPending`. Keep-plan and debug-export actions refuse while a preview/release commit is pending, so a provisional visual placement cannot be exported as evaluated geometry.

For the original direct-edit release, source validation included TypeScript checking against the generated project's actual LensifyTS declarations and installed SIK/UI Kit sources, esbuild parsing, and a Node harness using analytic inverse transforms. The harness checked floor projection, preview immutability, one deferred revision/evaluation, illegal-placement rollback and bed locking. The separate actual Preview pass then established SIK delivery in miniature and 1:1. Full-scale testing used a disclosed setup call to bring the bench into the fixed camera's view before real injected gestures; it is not counted as an interaction result. Physical drag comfort remains untested.

The final architectural helper also passed mesh checks: the shared rounded box has 486 vertices/768 triangles; the cylinder and lamp shade each have 102 vertices/96 triangles. All positions and normals are finite, all normals are unit length, indices stay in range, triangle winding faces outward and generated coordinates stay within the unit bounds. These validate authored geometry, not lighting or the final composition.

## Original native integration findings (7 November 2026)

The final native pass corrected the MeshBuilder upload calls to `appendVerticesInterleaved(vertices.flat())` (the generated rows contain interleaved attributes), added the optional unlit evidence-material input, and retained furniture collider roots/menu controls across rebuilds so SIK cursor caches never point at destroyed interaction targets. Visual child meshes still refresh, and every geometry check/transaction remains unchanged. The editor scene uses Simple PBR at roughness .78/metallic 0, ambient fill .55 and a warm directional key at 1.25. Actual SPECS 27 Interactive Preview ray drags passed miniature and 1:1 projection, deferred one-revision commit, boundary/overlap rollback and locked-bed refusal. A full production QR rendered in native Preview decoded with ZXing and matched the runtime share URL; its public JSON/SVG export matched final revision 11 and exact inputs. See the [public native record](../devpost/native-preview.md) and [sanitized measurements](../devpost/media/native-verification.json).

Read-only inspection of the installed SIK explains the lifetime decision: `Interactable.release()` delegates to `InteractionManager.deregisterInteractable()`, which clears active hits and collider caches but does not flush the cursor's private overlap/trigger caches. Those caches update in batches and may pause with an inactive cursor. A fixed destruction delay cannot establish that every reference is gone. Keeping the small, bounded set of targets alive avoids private cursor APIs and timing assumptions. ColliderUtils revalidates transforms and shape dimensions each frame, so movement and miniature/1:1 changes retain current hit geometry. No installed package or Cache file was patched for this fix.
